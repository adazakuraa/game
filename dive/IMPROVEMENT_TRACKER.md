# IMPROVEMENT_TRACKER.md

ダイビングゲームの改善要望を、原文の内容を削らずに管理するためのトラッカー。
各項目は実装・確認後に状態を更新する。要望の統合によって意味や条件を失わないこと。

## 運用ルール

-   [ ] 以下の要望を、明示的な指示なしに削除・省略・簡略化しない。
-   [ ] 複数の要望を同じ機能で実装する場合も、個別のチェック項目は残す。
-   [ ]
    既存実装との重複がある場合は、実装済みかどうかを確認して状態を更新する。単に項目を削除しない。
-   [ ] 要望同士に矛盾や依存関係がある場合は、勝手に解釈せず記録する。
-   [ ]
    魚・生物の追加では、既存データとの重複を確認し、同一種を二重登録しない。
-   [ ] 実装状態は `未着手` / `調査中` / `実装中` / `実装済み` /
    `確認済み` / `保留` のいずれかで管理する。
-   [ ] 「実装済み」と「動作確認済み」を区別する。
-   [ ] 本ファイルの項目数や内容を、トークン節約などを理由に減らさない。

## Phase 4：魚のAI・生態・撮影・行動イベント

### 魚の分布・群れ・逃走

-   [ ] 魚が一箇所に集まりすぎている場所を、もう少し分散させる。
-   [ ] 魚を集まらせてもよいが、その場合は2〜3種類くらいの魚だけにする。
-   [ ] ユーザーが近寄ると魚が一箇所に固まってしまう問題を修正する。
-   [ ] 居場所が決まっている魚は、極端に逃げすぎないようにする。
-   [ ]
    サンゴ礁では普通サンゴの周りに魚がいるため、魚が全くいないサンゴが多数ある状態を修正する。
-   [ ]
    サンゴ礁の魚の種類が多すぎるため、他の環境の魚を増やして、偏りが大きく生まれないようにする。
-   [ ] 海底遺跡・ブルーホール・洞窟は、魚の種類が多少少なくてもよい。

### イルカ

-   [ ] イルカがずっと周りを回り続けることがある問題を修正する。
-   [ ] イルカは30秒くらいついてきてくれる程度の挙動にする。

-   [ ] 海中で餌をまいたら魚が寄ってくる機能を追加する。
-   [ ] 寄ってくる魚が多すぎないようにする。

-   [ ] 餌は食堂で買うようにする。

### カメラ・撮影判定

-   [ ]
    遠くの魚や、岩の奥などで視界に映っていない魚にもカメラが「???」と反応してしまう問題を修正する。
-   [ ] 写真の判定対象は、あくまで写真の枠に直接映っている魚だけにする。

### タコ

-   [ ] タコに近づきすぎたら吸盤で絡まれるようにする。
-   [ ] タコに絡まれたらエアが減るようにする。

### 天候と出現

-   [ ]
    天候によって、出現する魚が多少変わるようにする（例：晴れ・曇り・雨・荒天などで、出現する種類や出現率が変化する）。
-   [ ]
    変化の度合いは極端にせず、特定の天候でしか出ない魚が図鑑や依頼の達成を阻害しない範囲に収める。
-   [ ]

## Phase 8：魚・生物モデルの見た目刷新

-   [ ]
    現状の魚・生物モデルはコード生成の簡易モデルで、お粗末で現実の魚から程遠い。見た目を現実の魚に近づけるよう刷新する。
-   [ ]
    目標水準は写真そのものではなく、シルエットと動きが本物らしく見える水準とする。スマホの描画負荷を最優先する。
-   [ ]
    近景の主役となる魚は、CC0など無料で再配布可能な3Dモデルの活用を検討する。そのままでは重い場合は、ポリゴン削減・テクスチャのベイク・glTF化でスマホ向けに軽量化する。
-   [ ]
    3Dモデルが使えない魚は、生成モデルの作り込みで対応する。体の断面プロファイル、ヒレの形状、模様、泳ぎのうねりを実物に近づける。
-   [ ]
    遠景の魚は簡易モデルや写真スプライトで数を稼ぎ、近景にだけ描画コストをかけるLODの使い分けをする。
-   [ ]
    使用するアセットは無料かつ再配布可能なライセンスのものに限る。出典とライセンスは CREDITS.md に記録する。有料アセット・有料APIは使わない。
-   [ ]
    アセットの取得・加工（軽量化）とライセンス確認は Muse が担当し、ゲーム内への組み込みとアニメーション調整は Claude が担当する分担を前提とする。
-   [ ]
    マテリアルとライティング（PBR、水中らしい光の表現）もあわせて見直し、モデルの刷新効果を底上げする。
