## 手順

### ステップ1：設計（Opus）

- Phase 2 の全項目について、現行コードのどこをどう変えるかを `dive/docs/PHASE2-DESIGN.md` に書き、実装前にコミットする。特に次は設計で決め切ること：
  - エア表示：bar 表示のみとし、「何分持つか」の具体表記と残り時間表示をなくす。初期ボンベは水深2mで約3分持つ性能を、現行のエア消費モデル（水深による消費倍率を含む）へ換算して数値で示す
  - 写真報酬：現在値の約7分の1への引き下げ。あわせて Phase 1 で仮置きした章の報酬額（§5.2）も、引き下げ後の写真報酬・装備価格・依頼報酬とのバランスで見直し、確定額を設計に書く（トラッカー未解決事項「写真報酬を約7分の1にした後、装備価格・依頼報酬・進行速度とのバランスを確認する」への回答を設計に含める）
  - 装備解放：水中ライトと銛の解放を中盤へ遅らせる具体的な解放条件。解放条件は割合（%）でなく発見した魚の絶対数で判定し、魚の総数が増えても解放が難しくならない形にする（分母に総数を使わない）。図鑑埋めはやり込み要素の位置づけを維持する
  - 浮上制限：一時停止ボタンからは浮上できないようにし、「どこからでも浮上できるアイテム」を購入した場合に限りどこからでも浮上可能にする
  - ショップ表示：購入可能な商品は点滅させず明るい表示にする。メニュー画面では商品のネタバレをせず、「入荷まであと〜」式の表示では商品名を出さず「？」等にする

### ステップ2：実装（Sonnet）

- 設計に沿って実装する。変更は Phase 2 の範囲に必要な最小限に留める。
- セーブ形式（`blue-depths-save-v1`）を変える場合は、旧データからの移行かキーの版上げを必ず入れる。解放条件の変更で既存セーブの解放状態が巻き戻らないよう注意する。
- 検証：`cd dive && npm install && npm run artifact` が通ること。テストフック／自動プレイ（Playwright）で、エア表示（barのみ・残り時間なし）、写真報酬の新額、解放条件（発見数ベース）、一時停止から浮上できないこと、浮上アイテム購入後の浮上可、を確認する。

### ステップ3：終了処理

- トラッカー Phase 2 のチェックボックスと進捗サマリーを実態に合わせて更新する。Phase 1 の判断待ち C（報酬額）は、確定したら未解決事項側もあわせて更新する。
- `dive/RESUME.md` を現状に書き直す。
- コミットして自分の作業ブランチに push し、アーティファクトをスキル `publish-artifact` の手順で更新する。
- 文脈使用率が約60%に達したら現在のステップを終えて新規作業を始めず、約70%で引き継ぎを書いて新セッションへ移る（スキル `session-handoff`）。

## 制約（再掲）

- 有料素材・外部 API・外部 CDN は使わない。
- スマホのタッチ操作が主前提。
- 依頼内容・条件・数値を勝手に要約したり削ったりしない。判断に迷う点は設計文書に「確認が必要な点」として残し、勝手に決めない。
