## Phase 1（5件）

### P1-1チュートリアル未完走で浮上すると夜に詰む
- 事実：endDive は quick 以外では clock を夜（780）に固定する。食堂ボタンは `!save.tutorial` で非表示。「しおさい亭へ帰る」ボタンは `night && save.tutorial` の時だけ表示。夜・ライトなしでは startDive が拒否される。結果、チュートリアル途中で浮上（気絶も同じ）すると食堂へ行く経路がない。
- 修正方針：夜の帰還経路をチュートリアルの完了状態に依存させない。`renderDaytime` の帰るボタンの表示条件から `save.tutorial` を外し（夜なら常に出す）、食堂に入れば女将さんの導入がそのまま進む形にする。あわせて、ボート画面の食堂ボタンの `!save.tutorial` 非表示が夜の経路を塞いでいないか確認し、塞ぐなら夜だけは例外にする。チュートリアルの後続ステップが食堂訪問を前提に壊れないことも確認する。

### P1-2boardOn の旧セーブ移行が新規プレイヤーにも効く
- 事実：loadSave の `if (sv.dives > 0) { sv.boardOn??= true; …}` が毎ロード走る。新規プレイヤーが1ダイブ後に再読み込みすると、2日目朝の女将さんの掲示板紹介（kitchen 側）を通らずに掲示板が解禁される。
- 修正方針：Phase 2 の `p2` 移行と同じ方式にする。新規セーブには作成時に移行済み印（例：`p1`）を付け、移行は印のない旧セーブにだけ適用する。既に boardOn が確定しているセーブ（紹介済み・移行済み）には影響させない。

### P1-3「銛が解放されたら食堂で依頼を受ける」のトラッカー [x] が実態より進んで見える
- 暫定決定（AR）：新しく「依頼を受ける」流れは作らない。現行（手銛を持つと食堂に注文票が出る）を実装として確定し、トラッカーの注記を実態に合わせて書き直す。コード変更なし。

### P1-4コーチとトーストの重なり
- Phase 7 でコーチは上部 118px に移った。現在の styles.css で #toast の位置を確認し、390px 幅でコーチ表示中にトーストが重なるかプローブで測る（両方を表示して矩形を比較）。重なる場合だけ、コーチ表示中はトーストをコーチの下へずらす（Phase 7 の #map-found と同じ `:has(#coach:not(.hidden))` の手法でよい）。重ならないなら「再現せず」で閉じる。

### P1-5死んだデータ・文書の差
- TutStep の未使用メンバー（hold）は、参照がないことを確認できれば削除してよい（動作変更なし）。okami の形と「しおさい亭」のボタン名は現行を正とし、コード変更なし。報告に「対応不要（現行が正）」と書く。

## Phase 2（5件＋追加1件）

### P2-1第4章のライト文言が入荷済みでも「図鑑を増やすと入荷する」になる

- 修正方針：`stockGap('torch') > 0` の時だけ「入荷する」文言にする。入荷済み・未所持の時は状態に合う文言（購入を促す言い方。他の章の文言の調子に合わせる）に分ける。

### P2-2既存プレイヤーのタンク容量が下がる

### P2-3シグナルフロートの入荷通知が既存プレイヤー（図鑑30種以上）に出ない

- 修正方針：入荷通知を「未通知の入荷済み商品」ベースにする。最小の実装として、通知済み商品の集合をセーブに持ち（例：`save.announced`）、ロード時またはボート表示時に未通知の入荷済みがあれば1回だけ通知する。再読み込みのたびに出ないこと。

## Phase 4（8件）

### P4-1餌の食性判定の語順・部分一致
- 事実（bait.ts の DIET_WORDS）：weed の 'ハギ' が先に当たり、カワハギ・テングカワハギ・モンガラカワハギ が海藻だんごに寄る（設計は meat）。plankton の 'アジ' が アジアコショウダイ（大型）・カスミアジ・ギンガメアジ に当たる。'ハタ' が ハタタテハゼ（極小のハゼ）に当たって meat になる。
- 修正方針：具体的な語ほど先に判定する（語の長い順・種名に近い語を優先）。少なくとも次を満たすこと：カワハギ系（カワハギ／テングカワハギ／モンガラカワハギ）→ meat、アジアコショウダイ → meat 側（語 'コショウダイ' を meat に足す等）、カスミアジ・ギンガメアジ → meat、ハタタテハゼ → meat にしない（'ハゼ' を含む種は語判定から外して大きさ・行動の代替判定へ）。既存の正しい判定（例：マアジ等の小型のアジ類 → plankton、藻食の種 → weed）が壊れないようにする。対象の種が実データに存在するかは species データで確認すること。

### P4-2餌の代替判定が設計より広い
- 設計 §3.1 は「0.15m 以上の単独・底の魚 → 肉食」。実装は school でも meat になる。設計どおり単独・底生に限る。

### P4-3leash の力の合成が設計どおりでない
- 設計 §1.4・§9.3 は「leash を超えたら逃走の力を 0 にして戻す」。実装は逃走の力を加えた後に戻る力を足す引き合いになっている。設計どおり、範囲外では逃走力を入れず戻る力だけにする。

### P4-4餌の誘引が非アクティブな種を数え、全走査が毎フレーム
- baitStep が rt.active を見ずに数え、上限（10匹・3種）を描画されていない個体が占有しうる。設計 §3.3 どおり active な個体だけ数える。あわせて全走査は設計どおり2秒ごとに間引く（候補の数え直しだけでもよい。負荷を増やさない形で）。

### P4-5refreshBaitUi が毎フレーム DOM を書く
- textContent と style.color は、値が変わった時だけ書く（前回値を保持して比較）。

### P4-6餌の雲がダイブ終了後に残る可能性
- endDive でも clearBaitVisual を呼ぶ（既に startDive では呼んでいる）。ボート画面に残らないことをプローブかコードで確認する。

### P4-7好奇心の状態がダイブをまたぐ
- reshuffle で cur／curT をリセットする（他の状態がダイブごとに初期化されるのと揃える）。

### P4-8設計文書内のしきい値の食い違い
- ハナヤサイサンゴの登録しきい値が §1.1（半径0.6m）と §9.2（sc > 0.4）で違う。実装は §9.2。
- 暫定決定（AU）：手順側の §9.2 を正とし、§1.1 の記述を §9.2 に合わせて直す（文書のみ）。
- 同じ項の他の2点（雨の夜行性の扱い、前日の荒天判定）はレビューで「実害なし」と確認済み。対応なし。
