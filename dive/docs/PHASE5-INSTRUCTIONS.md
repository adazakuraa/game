## 手順

### ステップ1：設計（Opus）— ここまでで停止する

- Phase 5 の全項目について、現行コードのどこをどう変えるかを `dive/docs/PHASE5-DESIGN.md` に書き、コミットして push する。**実装には入らない**（実装は Muse 側で行う。設計の最後に「実装手順」の章を付け、変更ファイル・変更内容・検証方法を実装者がそのまま進められる粒度で書くこと）。特に次は設計で決め切ること：
  - 海マップの表示：航空写真風の表現（サンゴ礁がありそう、青が濃いから深そう、といった程度の情報だけが分かる）、遺跡など人工物を表示しない、未発見ポイントは「×？」表示・残り総数を分からなくする、マップ端を黒くせず海が続いて見せる＋端まで行くと「これ以上は進めない」表示。現行ミニマップ／全体マップの描画方式（地形データからの生成か、テクスチャか）との整合と、スマホでの描画負荷
  - 遺跡・ブルーホール・洞窟・沈没船：遺跡を太陽のピラミッドのような形に、遺跡に宝箱、各マップに宝箱1つ程度（中身は限定装備、または未発見の光景へのヒント）、沈没船にも宝箱、同じような場所に固まった地点の分散、水中洞窟を上から見ると穴が空いて見える問題の修正、洞窟の繋がりがマップで分からないようにする、洞窟の上の砂地への砂地特有の魚の配置。宝箱の開封状態の保存（セーブ形式への影響を含む）
  - 写真スポット・光景：Phase 3 実装（光景サークル、撮影スポット9か所、初回報酬）との照合。トラッカー Phase 5 の同名項目とどこが重なり、残りは何か（範囲を示す円など）を項目単位で切り分ける
  - 深海表現：マリンスノーの白い粒子が沖の浅いところから見える問題の原因と、深海に入ってから表示する条件
  - マップ固有種：各マップの固有魚の現状棚卸し（マップ×種の対応表）と、「各マップ少なくとも10種」への不足分。不足分の埋め方（既存種の出現地域の調整で足りるか、新規種が要るか。新規種の追加自体は Phase 12 の範囲との切り分け）
- 判断に迷う点は設計文書に「確認が必要な点」として残し、暫定案を添える。

### ステップ2：実装（Muse）

- 設計に沿って Muse が実装する。変更は Phase 5 の範囲に必要な最小限に留める。
- 地図や地形の見た目変更は、Phase 8（モデルの見た目刷新・LOD）の前提を崩さない。
- セーブ形式（`blue-depths-save-v1`）を変える場合は、旧データからの移行かキーの版上げを必ず入れる。
- 検証：`cd dive && npm install && npm run artifact` が通ること。テストフック／自動プレイで、マップ表示（未発見の秘匿・端の扱い）、宝箱の開封と中身、洞窟の見た目、マリンスノーの表示条件、固有種の数を確認する。

### ステップ3：終了処理

- トラッカー Phase 5 のチェックボックスと進捗サマリーを実態に合わせて更新する。
- `dive/RESUME.md` を現状に書き直す。
- コミットしてブランチに push する（アーティファクト更新は節目のみ。動作確認は GitHub Pages で行う）。

## 制約（再掲）

- 有料素材・外部 API・外部 CDN は使わない。
- スマホのタッチ操作が主前提。描画負荷はスマホ最優先。
- 依頼内容・条件・数値を勝手に要約したり削ったりしない。判断に迷う点は設計文書に「確認が必要な点」として残し、勝手に決めない。
