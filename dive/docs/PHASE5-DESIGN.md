## 1. 海マップの表示・探索性

トラッカー項目：遺跡などを表示しない／航空写真のような表現／サンゴ礁がありそう・青が濃いから深そう程度の情報／探索性を高める／未発見ポイントは「×？」／残り何個か分からない／端を黒くしない／端の先も海が続いて見える／端へ行くと「これ以上は進めない」。

### 1.1 描画方式（決定）：今の「起動時に地形関数から 1 回生成」を維持し、中身を航空写真風に作り替える

- 画像テクスチャ（外部素材）は使わない（共通方針：手続き生成）。今の方式は、生成が起動時 1 回・毎フレームは `drawImage` だけなので、スマホでも軽い。この構造は変えない。
- 変えるのは `buildChart` の**色の決め方**と**サンプルする高さ関数**だけ。ミニマップ・全体マップの描画コードは「余白の扱い」（§1.5）以外そのまま。

### 1.2 航空写真風の色（決定）

上空から海を撮った写真のように、**「海底の色」を「水の色」が深さとともに覆い隠す**モデルにする。等深線・陰影（hillshade）・ゾーン単位の色味は**全部やめる**。

```
bottom  = 海底の色（bottomMaterial の砂・サンゴ・岩・深場の泥。§1.3 の自然地形で）
water   = 深さ d の水の色（下の表を補間）
detail  = exp(-d / 9)            // 海底が透けて見える度合い。d=9m で 37%、20m で 11%、30m で 4%
color   = mix(water, bottom × 0.9 + 0.1, detail)
          × (1 + 0.06·ゆらぎ)    // 水面のさざ波：低周波 simplex を 1 回（per-pixel、heightAt は呼ばない）
```

| 深さ d | 水の色（sRGB の目安） | 見え方 |
| --- | --- | --- |
| 0〜2m | #a8eadf | 白い砂が透ける明るいエメラルド |
| 6m | #4fc6cf | 明るい水色 |
| 15m | #1f97c2 | 青 |
| 40m | #0f62a8 | 濃い青 |
| 120m | #0a3f86 | 紺 |
| 400m+ | #082c6a | 深い紺（**黒にはしない**。最小でもこの色） |

- サンゴ礁がありそう：浅いサンゴ礁は `bottomMaterial` の「サンゴ・藻の茶〜紫のまだら」が detail 経由で茶色っぽい斑点として透ける。礁の縁（ドロップオフ）で色が一気に濃くなる＝「ここから深い」。
- 海藻の森：水面まで伸びるケルプを、`kelpWeight > 0.4` の所に低周波ノイズで「暗い金茶色のまだら」（#5a5a30 を 45% 程度）として重ねる（上から見た海藻のキャノピー）。
- 流氷の入り江：`zoneAt === 'cold'` の所に、ノイズのしきい値で白い流氷片（#e8f4f8、ノイズで不規則な形）を重ねる。flora の流氷の実位置とは一致しなくてよい（上空写真の「雰囲気」）。
- ゾーンの境界が長方形に見えないよう、ゾーン ID で色を切り替える処理は使わない（`bottomMaterial` と深さだけで色が決まる）。
- 解像度は今と同じ 2.5m/px。描いたあと全体を 1 回だけ軽くぼかす（`ctx.filter = 'blur(0.6px)'` で自分自身に drawImage。filter 非対応なら省略してよい）。

### 1.3 人工物・洞窟の繋がりを地図に出さない（決定）：地図専用の「自然地形の高さ」`chartHeightAt`

- `layout.ts` の高さ計算を内部関数 `heightCore(x, z, mode)` にまとめ、外向けに 3 つ出す：
  - `heightAt(x, z)`（mode 0）：**今と同じ**。当たり判定・生き物・足元。挙動を変えない。
  - `surfaceTopAt(x, z)`（mode 1）：見える地表。水中洞窟の溝を**天井がある所では彫らない**（§2.3 で地形メッシュに使う）。
  - `chartHeightAt(x, z)`（mode 2）：地図用。mode 1 に加えて、**遺跡（ピラミッド・階段のスロープ・道の溝）と沈没船の掘れ跡を足さない**。
- mode は引数を westHeight の奥まで通さず、モジュール内の変数で切り替える（`let MODE = 0;` を wrapper で一時的に 1/2 にして戻す）。`heightAt` 自体のコストは「MODE の比較 1 回」しか増えない。
- これで地図からは：遺跡の四角い段々・洞窟の通路の線が消える。**セノーテの縦穴（直径 18m）とブルーホールの円は自然地形なので残る**（「青が濃いから深そう」の範囲。確認点 X）。
- 地図の上に描くもの（既知ポイント名・ブイ・ボート・依頼／光景／スポットの円）は今のまま。宝箱は地図に描かない（§3）。

### 1.4 未発見ポイントを「×？」、残り個数を分からなくする（決定）

- ボート画面の行き先一覧（`Game.ts` の `if (hiddenN)` ブロック）：表示を「未発見のポイント **×？**」に変える。行は「未発見が 1 つ以上あるときだけ出す」を**やめ、常に出す**（全部見つけても出す。行の有無で「もう無い」が分かってしまうため）。説明文は「まだ知らない海がある」→「海は広い。まだ何かあるかもしれない」（全部見つけた後も嘘にならない文）。
- アルバムの写真スポット一覧（`renderAlbum`）：**未発見マップのスポットは行ごと出さない**。見出しの「写真スポット ◯ / 9」の分母は「**◯ / ？**」にする（総数でマップ数が推測できるため）。発見済みマップの未撮影スポットは今どおり「？？？＋マップ名＋額」。
- 図鑑の章・光景の「？？？」は今のまま（ポイント数は分からない）。
- 宝箱の数も出さない（§3.6）。

### 1.5 マップの端（決定）

**(a) 地図：端を黒くせず、海が続いて見える**
- 海図を作るとき、世界（`WORLD`）の外側に**余白 M = 120m** を足した範囲で canvas を作る（`(860+240)/2.5 = 440px × (1150+240)/2.5 = 556px`）。余白の画素は `heightAt` を呼ばずに作る（負荷対策）：
  - 世界の縁の画素の「深さ」をそのまま外へ延ばし、沖側（上＝+z）と左右は外へ行くほど少しずつ深く（+0.3m/m、上限 425m）、低周波ノイズで揺らす。色は §1.2 と同じ式（detail は深さから）。
  - 岸側（下＝-z、z < -70）は**島の浜**：白い砂浜（#e8dcc0）→ 内陸の緑（#5f8a4a）へ。ここだけは「海が続く」ではなく陸（ラグーンの岸がもともと島の浜なので自然）。確認点 Y。
- ミニマップ（半径 75m）は、ダイバーが `WORLD` 内にクランプされるので、余白 120m があれば黒が見えることはない。念のため塗りつぶし色 `#020c14` を、海図の縁の色に近い `#0b3a78` に変える。
- 全体マップ：世界の部分（`WORLD`）を今と同じ縮尺で画面に収め、**余白ごと描く**（余白が画面の外へはみ出すのは構わない）。それでも余る所は、余白の縁の色で塗る（上と左右は深い紺 `#082c6a` 系、下は陸の緑）。世界の境界線は描かない。
- 「▲ 沖」「岸 ▼」の文字は、世界部分の上端・下端の位置のまま。

**(b) 3D：地形の端が見えない**
- `terrain.ts` `update` のチャンク生成範囲 `WORLD ± 60` を `WORLD ± (radius + CHUNK) = ± 135` に広げる。ダイバーはクランプされるので、生成されるのは端に近いときだけ（チャンク数の上限は今と同じ、半径 95m の円の中）。
- `heightAt` は世界の外でも連続した値を返す（沖の断面・流氷の入り江の浜など、式が外へそのまま延びる）ので追加の地形関数は要らない。実装後に四辺でスクショ確認（§9.8）。

**(c) 端へ行くと「これ以上は進めない」**
- `updateDiver` のクランプ直前に「端までの距離」を測る：`edge = min(p.x - minX, maxX - p.x, p.z - minZ, maxZ - p.z)`。
  - `edge < 12m`：外向きの速度成分を毎フレーム弱める（`vel` の外向き成分 × `(edge/12)`）＝潮に押し戻される手ごたえ。
  - クランプが効いた（＝端に触れた）とき、4 秒に 1 回 `toast`（'warn'）：
    - 沖・左右：「潮の流れが強い。これ以上は進めない（ボートに戻れなくなる）」
    - 岸側（z が minZ）：「ここから先は浜。これ以上は進めない」
  - 深海（ADS）でも同じ（文言は前者）。
- 今の深度制限のトースト（`lastWarn`）と同じ仕組みでよい（別タイマー `lastEdgeWarn`）。

### 1.6 スマホでの描画負荷

- 毎フレームの負荷は変わらない（ミニマップは 4 フレームに 1 回の `drawImage`、全体マップは開いたときだけ）。
- 起動時の海図生成：画素数は世界部分が今と同じ 158k、余白は `heightAt` を呼ばない安い計算。`bottomMaterial` を追加で呼ぶが、**detail が 2% 未満（d > 35m）の画素では呼ばない**（遠い沖・深海は水の色だけ）。等深線・陰影の近傍参照が無くなる分も軽くなる。
- 目標：生成時間を `performance.now()` で計測し、変更前の 1.5 倍以内（実装時に前後を README か RESUME に記録）。超えたら `bottomMaterial` の呼び出しを 2 画素に 1 回（5m 間隔）にして間を補間する。
- 3D：チャンク範囲の拡大は端の近くでだけ数チャンク増えるだけ。

## 2. 海底遺跡・ブルーホール・洞窟・沈没船

### 2.1 海底遺跡を「太陽のピラミッド」の形に（決定）

テオティワカンの太陽のピラミッドの特徴＝**正方形の底面・5 段の傾斜した壁（タルー）と平らなテラス・正面に一直線の大階段・頂上の平らな台と神殿**。これを水深に収まる大きさで作る。

- 中心 `RUINS`（-330, 505）、底 -22m（今と同じ）。`westHeight` の段々（`r = max(dx/1.3, dz)` と `stepped`）を、**正方形**（`r = max(|dx|, |dz|)`）の 5 段に置き換える：

| 段 | 下端の半幅 | 壁の高さ | 壁の上端（テラス）の高さ（底から） | テラスの奥行き |
| --- | --- | --- | --- | --- |
| 1 | 30m | 4.5m | 4.5m（-17.5m） | 4.5m |
| 2 | 24m | 4.0m | 8.5m（-13.5m） | 4.0m |
| 3 | 18.5m | 3.0m | 11.5m（-10.5m） | 3.5m |
| 4 | 13.5m | 2.5m | 14.0m（-8.0m） | 3.0m |
| 5 | 9.0m | 2.0m | 16.0m（-6.0m）＝頂上の台（18m 四方） | — |

  - 壁は内側へ 1.5m 傾ける（下端の半幅 w → 上端 w-1.5、`smoothstep` で角を少し丸める）。地形グリッドが 1m なので、段の角は多少なまってよい。
  - 表面に今と同じ小さなノイズ（0.15m）を残し、石積みらしさは `flora.ts` の石ブロック（下記）で出す。
- **大階段**：北面（+z、門と道の側）の中央、幅 7m（x = RUINS.x ± 3.5）。地形（`heightAt`）は階段の部分だけ**一直線のスロープ**（z = RUINS.z+30 で底 → z = RUINS.z+9 で頂上の台）にする（当たり判定はスロープで十分）。見た目の段は `flora.ts` でインスタンスの箱（幅 7m×高さ 0.6m×奥行き 0.8m を約 27 段）をスロープに沿って並べる（当たり判定なし＝`add`、スロープと同じ面に乗る）。左右に低い袖壁（箱 2 列、`solid`）。
- **頂上の神殿**：頂上の台の中央に小さな建物（外寸 7m×7m×3.5m、壁厚 0.8m、**北側に入口**（幅 2.4m×高さ 2.4m）、平らな屋根）。箱の組み合わせで `solid`（当たり判定あり）。中に宝箱（§3）。
- 柱の輪（26 本）は、底面（半幅 30m）に刺さらないよう半径を 36〜52m に広げる（今の `rr = 26 + (k % 3) * 9` → `36 + (k % 3) * 8`、×1.3 の楕円もやめて円に）。門（z+52）と道（z+28〜+70 の溝）は、道の始まりを階段の下（z+30）に合わせる（`z > RUINS.z + 28` → `+ 31`）。崩れた石ブロック（70 個）は `max(|dx|,|dz|) < 31` の範囲（ピラミッドの上）を避ける。
- 写真スポット「海底遺跡の石段」（`spots.ts`）は大階段に合わせて、円の中心を (RUINS.x, RUINS.z+40)、見どころを (RUINS.x, y=-15, RUINS.z+20)（階段の中ほど）にする。
- 地図（`chartHeightAt`）にはピラミッド・階段・道を出さない（§1.3）。

### 2.2 固まっている地点の分散（決定）：ブルーホールを東の沖へ移す

- 今は遺跡・ブルーホール・洞窟が西の一列（x=-330）に並び、地図で「西の帯に名所が固まっている」と分かる。**ブルーホールを東の沖の浅い台地（海山）に移す**：
  - `BLUEHOLE = { x: 300, z: 600, r: 27, depth: 55 }`。まわりを半径 70m の白砂の台地（-7m）にし、半径 70〜105m で沖の海底（約 -140m）へ落とす（海山の崖）。台地の縁は角度方向のノイズで不規則に（円が地図でくっきりしすぎないように）。

### 2.3 水中洞窟を上から見ると穴が空いて見える（決定）

原因（§0）：天井の上面が「地形と違う材質・違う高さの平板」で、台地の中で浮いて見える／沈んで溝が覗く。
直し方：**地形メッシュ自体が天井の上を覆う**ようにし、洞窟の床と壁は別メッシュにする。

1. `terrain.ts` `build`：頂点の高さ・法線（差分）・AO（ラプラシアン）を `heightAt` → `surfaceTopAt` に変える（洞窟の溝は天井のある所では彫られない＝台地の砂が途切れずに続く）。セノーテの縦穴（`caveRoofAt` が null になる半径 `CENOTE.r + 1.5` の内側）と、その縁から通路の入口へは今どおり彫る（`surfaceTopAt` は `dist(cenote) < CENOTE.r + 2` の所だけ溝を残す）。
2. `flora.ts` cave ブロック：天井の**上面シート（`sheet(true)`）を削除**。下面シート（天井の裏）は残す。
3. 同じく cave ブロックに「**洞窟の内側（床と壁）**」のリボンメッシュを足す：通路の点列 `pts` に沿って、横方向 J=16 分割、`-(w+3.0)`〜`+(w+3.0)`、高さは `heightAt`（＝今の溝の形そのもの）。上向き（法線 +y 側が表）。材質は天井と同じ `rockMat`（暗い洞窟内はライトで照らすので十分）、`receiveShadow`。セノーテの縦穴の内側（`dist < CENOTE.r + 1.2`）は地形メッシュが見せるので省く。
4. 当たり判定（`heightAt` と `caveRoofAt`）・生き物・ガイドラインは変えない。地形メッシュは片面描画なので、洞窟の中から見上げても地形の裏面は描かれず、天井の裏シートが見える。

## 5. 深海表現（マリンスノー）

### 5.1 原因

- マリンスノーの明るさ `uAmb = (0.1 + 0.32·e^(-深さ/30) + (深さ>150 ? 0.05 : 0))·(1 - 暗さ·0.85)` は**深さ 0m で最大（0.42）**で、場所の条件が無い。つまり実は浅い海ではどこでも出ている。
- ラグーンやサンゴ礁は水の色が明るい水色（`ZONE_WATER` の lagoon 0.035/0.27/0.36）なので、白い点（加算合成）が背景に溶けて目立たない。**沖（offshore：0.006/0.09/0.30、透明度 64m）とドロップオフは水が最も暗い青で透明度も高い**ので、同じ白い点がくっきり浮いて見える。これが「沖の浅い所から白いものが見える」の正体。
- ライトを点けたときの円錐（`uLight`）の白い粒も同じ点で、夜の浅い海でも出る。

### 5.2 表示条件（決定）

- 「深海」＝深海マップ（大気圧潜水服で潜る `deep`、水深 170〜430m）。スキューバの限界は 58m なので、**白い粒は ADS で深く降りたときだけ**出る。
- `environment.ts`：`snowK = smoothstep(120, 170, depth)` を作り、白い成分（`uAmb` と `uLight`）に掛ける：
  - `uAmb = (0.1 + 0.05) · snowK · (1 - D·0.85)`（深海での今の値 0.1+0.05 を基準。浅いほど強い項 `0.32·e^(-d/30)` は削除）
  - `uLight = (diverLight.intensity/30) · 0.9 · snowK`
- 夜光虫・夜のプランクトンの青い光（`uGlow`）は別の演出（光景「夜光虫の青い光」）なので**今のまま**（浅い夜の海で光る）。
- 負荷：`snowK == 0 && uGlow < 0.01` のときは `snow.visible = false`（2200 点の加算描画をスマホで丸ごと省く）。

## 8. 確認が必要な点（暫定案で進める）

Phase 4 までの A〜W に続けて X〜AG とする。

- **X** 地図にブルーホールの円とセノーテの点（自然地形）は出す。「青が濃いから深そう」の範囲と判断した。人工物（遺跡・沈没船）と洞窟の通路は出さない。ブルーホールも消したい場合は `chartHeightAt` で穴を埋める（1 行）。
- **Y** 地図の岸側（南）の外は「島の浜と陸」にした。沖・左右は海が続く。南も海にしたいなら余白の色を沖と同じにする。
- **Z** 遺跡のまわりの沈没船 3 隻（墓場）は動かしていない。「固まっている地点」に沈没船も含むなら、1 隻をブルーホールの台地の崖下などへ移す。
- **AA** 限定装備 3 つ（エア −10%・速さ +10%・ボートの方向の矢印）の効果の大きさと名前は仮。
- **AB** 光景のヒントは「アルバムに名前と手記が出る」だけで、出現率は上げない。
- **AC** マリンスノーは ADS の深海（120m から出始め、170m で最大）だけにした。ブルーホールの底（55m）や夜の浅い海のライトの白い粒も消える。夜光虫の青い光は残す。
- **AD** ラグーン所属のうち `sandSpots` の種が実際はサンゴ礁の砂地にいる件は、Phase 5 では直していない（Phase 11 の「生息環境・水深・出現率が適切である」で扱う）。
- **AE** ヒカリキンメダイの二重登録（`hikarikinme` / `hikarikinme2`）は残した。Phase 12 の照合で 1 種にまとめるか判断する。
- **AF** 図鑑の一覧に 5 マップ（流氷・遺跡・ブルーホール・洞窟・海藻の森）を足す（`ZONE_ORDER` 1 行）。固有種を見せるために Phase 5 で入れる。並びは ラグーン→サンゴ礁→岩礁→ドロップオフ→沖→海藻の森→流氷の入り江→海底遺跡→ブルーホール→水中洞窟→深海。
- **AG** 「各マップに固有の魚 10 種」は、ダイブポイント 10 か所を「マップ」とし、ドロップオフと沖は 1 マップ、魚＝魚類（エイ・チンアナゴを含む）、固有＝出現位置の 80% 以上がそのマップ、で数えた。ブルーホールの移動先・ピラミッドの寸法も仮。

## 9. 実装手順（Muse 向け）

### 9.1 地形関数（`src/world/layout.ts`）

1. `heightAt` の本体を `function heightCore(x, z)` に移し、モジュール変数 `let MODE: 0 | 1 | 2 = 0` を置く。`export function heightAt(x,z){ return heightCore(x,z); }`、`export function surfaceTopAt(x,z){ MODE = 1; const h = heightCore(x,z); MODE = 0; return h; }`、`chartHeightAt` は MODE 2 で同様。
2. `westHeight` の洞窟部分：溝を彫る `hc = Math.min(hc, …)` を `if (MODE === 0 || rc < CENOTE.r + 2)` で囲む。

4. 沈没船の掘れ跡（`wreck scour pit`）を MODE 2 では足さない。

'ruins' : 'cave'`。
6. `DIVE_POINTS` の bluehole を (300, 545) に。
7. `caveTopAt(x, z): number | null` を追加（天井がある所の台地の高さ：`-2.6 + 0.6·ridged2(x·0.06, z·0.06, 3)`、無ければ null）。
8. 確認：`node` で `zoneAt` を格子に当てた ASCII 図（scratchpad）を出し、ブルーホールの台地・遺跡・洞窟の帯の位置を目で見る。
