## 手順

### ステップ1：設計（Opus）

- Phase 1 の全項目について、現行コードのどこをどう変えるかを `dive/docs/PHASE1-DESIGN.md` に書く。特に次は設計で決め切ること：
  - チュートリアルの新しい順序（現行4より前に5・6の内容を置き、「写真を撮ればお金が得られる」説明の後にエアの説明が来る構成）と、各ステップの表示位置（画面中央を避ける）
  - チュートリアル3が一瞬でクリアになる原因の特定と修正方針
  - 2枚目以降の写真の説明の見切れ修正と、説明をチュートリアル内に収める方針
  - ゲーム開始直後に浅瀬ラグーンの海中から始まる導入の流れ
  - 冒頭ストーリー：主人公は元々ダイビングをしており趣味で写真を撮っていた設定 → 腕を見込まれてスカウト → チュートリアル終了後に褒められて仕事の依頼へ。仕事には報酬を設定し、編集長の依頼をクリアしても報酬がない問題を直す
  - 時間システム：浮上したら強制的に夜、食堂で寝ると朝にできる。水中ライト解放後は夜にする手段も追加。朝／夜の切り替えは現在の時間で表示と動作が変わる単一ボタンにする
  - 女将さんのセリフ：朝・帰還時の一言、世界観の小分け説明（世界中の魚が集まる島、少し泳げば寒い海、海底遺跡の匂わせ）、後で解禁される装備の軽い匂わせ（有効性の示唆まで。解禁の明言はしない）、銛解放後に食堂で依頼を受ける流れ
  - 依頼掲示板のチュートリアル（女将さんの「島の人から依頼が来ているよ」から入る）
- 設計文書は実装に着手する前にコミットする（セッション内に残さない）。

### ステップ2：実装（Sonnet）

- 設計に沿って実装する。変更は Phase 1 の範囲に必要な最小限に留める。
- 経済バランスの詳細調整は Phase 2／Phase 11 の担当。Phase 1 では「編集長の依頼に報酬が付く」ことまでを実装し、金額の最終調整は設計文書に申し送る。
- セーブ形式（`blue-depths-save-v1`）を変える場合は、旧データからの移行かキーの版上げを必ず入れる。
- 検証：`cd dive && npm install && npm run artifact` が通ること。テストフック（`__THREE_GAME_TEST_HOOKS__`）や自動プレイで、チュートリアルの新順序と時間切り替えが実際に動くことを確認する。

### ステップ3：終了処理

- トラッカー Phase 1 のチェックボックスと進捗サマリーを実態に合わせて更新する。
- `dive/RESUME.md` を現状に書き直す（進んだ所・次の一手・判断待ち）。
- コミットして自分の作業ブランチに push し、アーティファクトをスキル `publish-artifact` の手順で更新する。
- 文脈使用率が約60%に達したら現在のステップを終えて新規作業を始めず、約70%で引き継ぎを書いて新セッションへ移る（スキル `session-handoff`）。

## 制約（再掲）

- 有料素材・外部 API・外部 CDN は使わない。アセットは手続き生成が原則。
- スマホのタッチ操作が主前提。縦横どちらでも崩れないこと。
- 依頼内容・条件・数値を勝手に要約したり削ったりしない。判断に迷う点は設計文書に「確認が必要な点」として残し、勝手に決めない。
