## 手順

### ステップ1：設計（Opus）

- Phase 4 の全項目について、現行コードのどこをどう変えるかを `dive/docs/PHASE4-DESIGN.md` に書き、実装前にコミットする。特に次は設計で決め切ること：
  - 魚の分布・群れ・逃走：魚が一箇所に集まりすぎる場所の分散。集まる場合は2〜3種類までにする。プレイヤーが近寄ると一箇所に固まる問題の原因と修正。居場所が決まっている魚が極端に逃げすぎない調整。サンゴ礁で魚がいないサンゴが多数ある状態の修正。サンゴ礁の種類の偏りを、他の環境の魚を増やして均す方針（総数の増やし方は、スマホの描画負荷の範囲内で）。海底遺跡・ブルーホール・洞窟は種類が多少少なくてよい前提
  - イルカ：周りを回り続ける問題の修正。30秒程度ついてくる挙動の具体的な仕様（ついてくる条件、離れる条件）
  - 餌・魚の誘引：海中で餌をまくと魚が寄ってくる機能。寄る魚が多すぎない上限。餌の種類ごとに寄ってくる魚を変える対応表。餌は食堂で買えるようにする（食堂の販売導線、価格は Phase 2 の経済バランスと矛盾しない範囲で仮置きし、判断待ちに記録する）
  - カメラ・撮影判定：視界に映っていない魚（遠く、岩の奥）に「???」と反応する問題の修正。判定対象を写真の枠に直接映っている魚だけにする判定方法
  - タコ：近づきすぎると吸盤で絡まれる仕組み。絡まれるとエアが減る仕様（減り方、抜け出し方、オキザヨリの −8bar 等の既存仕様との整合）
  - 天候と出現：天候（晴れ・曇り・雨・荒天）で出現する種類や出現率が多少変わる仕組み。変化は極端にせず、天候限定の出現が図鑑・依頼の達成を阻害しない範囲に収める設計。その日の天候を食堂の女将さんのアナウンスで伝える導線（Phase 1 の女将さんの一言の仕組みとの整合）

### ステップ2：実装（Sonnet）

- 設計に沿って実装する。変更は Phase 4 の範囲に必要な最小限に留める。
- 魚の総数を増やす場合は、描画負荷（ドローコール、ポリゴン、スマホでのフレームレート）に注意し、Phase 8（モデルの見た目刷新・LOD）の前提を崩さない。
- セーブ形式（`blue-depths-save-v1`）を変える場合は、旧データからの移行かキーの版上げを必ず入れる。
- 検証：`cd dive && npm install && npm run artifact` が通ること。テストフック／自動プレイ（Playwright）で、群れの分散、イルカの追従時間、餌の誘引、撮影判定（枠外の魚に反応しない）、タコの絡みとエア減少、天候による出現変化と女将さんのアナウンスを確認する。

### ステップ3：終了処理

- トラッカー Phase 4 のチェックボックスと進捗サマリーを実態に合わせて更新する。
- `dive/RESUME.md` を現状に書き直す。
- コミットして自分の作業ブランチに push し、アーティファクトをスキル `publish-artifact` の手順で更新する。
- 文脈使用率が約60%に達したら現在のステップを終えて新規作業を始めず、約70%で引き継ぎを書いて新セッションへ移る（スキル `session-handoff`）。

## 制約（再掲）

- 有料素材・外部 API・外部 CDN は使わない。
- スマホのタッチ操作が主前提。描画負荷はスマホ最優先。
- 依頼内容・条件・数値を勝手に要約したり削ったりしない。判断に迷う点は設計文書に「確認が必要な点」として残し、勝手に決めない。
