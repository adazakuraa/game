### (1) 潜水中の表示の大きさ・ボタンの大きさの設定
- **現行**：Phase 7（2026-11-25）にユーザーの報告で拡大した値のまま。`styles.css`：シャッター 118px（小画面 72px）、`.ctl` 70px（小画面 46px）、エアゲージ 124px（104px）、ミニマップ 118px、水深 44px、コーチの文字 18px（小画面 17px、`#coach` 幅 `min(460px, 100vw − 360px)`）。大きさの設定画面はない（ボートにはサウンドの切り替えだけ）。

  1. 既定値を一段小さくする（暫定：シャッター 96px、`.ctl` 58px、エア 100px、ミニマップ 100px、水深 34px、コーチの文字 15px・幅 `min(400px, …)`・余白を詰める、図鑑チップ・売上チップも 85% 程度）。小画面（`@media` の既存の段）も同じ比率で縮める。

  3. 保存：セーブの `ui?: { shutter: number; ctl: number }`（省略時 1）。進行度リセットでも消さない（端末ごとの好みなので）。
- 原則（桜井「画面は情報の取捨選択」）：海の中が主役。常時出る情報は小さく、触る物は親指で押せる大きさ（最小 44px）を下回らない。

### (31) スティックで前に進むと沈む
- **現行**：`Game.ts` 1586 行：進む向き `fwd` が**カメラの上下の傾き（pitch）を含む**。潜水開始時の pitch は −0.35（約 20° 下向き、1080 行）なので、スティックを上に倒すだけで斜め下へ進み、毎秒 約 0.8m 沈む。

### (11) サンゴやウニが浮いている
- **現行の推定**（実装時にまず計測する）：
  - サンゴ・海綿・岩（`world/flora.ts`・`scatter.ts`）は置き場所の**中心 1 点**の `heightAt` に底を合わせている。地形メッシュはチャンクの格子で三角形に近似されるため、斜面では置き物の縁の下の地面が中心より低く、片側が浮く。
  - ウニ（ウニ漁 `missions.ts` 542 行・`URCHINS`、図鑑のウニ類）は `surfaceAt`（岩やサンゴ頭の上も拾う）を使うが、`surfaceAt` が岩の**上面**を返した後に、その岩が LOD やチャンクの入れ替えで別の形になると浮いて見える可能性がある。
- **方針**：
  1. 計測用のプローブ（`scripts/probe-float.cjs`、新規）：各マップでサンゴ・ウニ・海綿など底に付く物のインスタンスについて、足元の四隅（半径 × 0.7）の地形メッシュの高さ（`surfaceTopAt`、あるいはメッシュへのレイ）と底面の高さの差を測り、0.15m 以上浮いている数と場所を出す。
  2. 置くときは足元の 5 点（中心＋四隅）の**最小値**に底を合わせ、さらに斜面の傾き × 半径だけ埋める（埋まる分は見た目上問題ない）。ウニは `surfaceAt` の最小値の側へ。
  3. 変更後に同じプローブで浮きが 0（または許容 0.15m 以内）を確認。地形自体は変えない（`terrain-dump` の差分 0）。

### (14) ボートの錨

### 現行

### 方針：吹き出しの仕組み（新規 `src/ui/talk.ts`）
- **見た目**：画面下寄りに話し手の顔アイコン（手続き描画の簡単な似顔：編集長・女将さん・漁師ゲンさん）と名前、吹き出しの本文。吹き出し以外は半透明の黒（`rgba(0,0,0,0.6)`）で暗くする。指す先がある段では、その要素の周りだけ穴を開けて明るく見せ（`box-shadow: 0 0 0 9999px …` の切り抜き）、指で押す印（脈打つ輪）を重ねる。
- **進み方**：
  - 「話」の段：画面のどこをタップしても次へ。最後の段で閉じる。
  - 「選ぶ」の段：吹き出しの中に 2〜3 個のボタン（「受ける」「あとで」など）。選んだ結果を呼び出し元に返す（Promise）。
  - 「操作させる」の段：指した要素だけ押せる（ほかは暗幕が受け止める）。押したら次の段へ進む（例：「ショップを押してみよう」→ ショップが開く → 「これがライト。買ってみよう」→ 購入ボタンだけ明るい）。
- **データ**：会話は台本の配列 `TalkLine = { who; text; target?: string /* CSS セレクタ */; wait?: 'tap' | 'click' | 'event:<名前>'; choices?: { id; label }[] }`。台本は `src/game/talks.ts`（新規）に ID 付きでまとめる（`TALKS.nightRest`・`TALKS.shopOpen` など）。
- **一度きり**：セーブに `talked?: string[]`（見た台本の ID）。同じ台本は二度出さない（章の会話は章ごと）。台本の途中で閉じたら（アプリを閉じた等）、次に同じ条件になったときに最初からもう一度。
- **割り込みの順番**：吹き出しは**キュー**で 1 つずつ。ボート画面に戻ったときに、①章の報酬・褒め言葉 → ②次の章の依頼 → ③機能の解放（F5）→ ④新アイテムの説明（F5）→ ⑤入荷の知らせ（トースト）の順。1 回のボート画面で出すのは最大 3 本、残りは次回（連続で長くならないように）。
- **潜水中**：画面を暗くすると危ないので、潜水中の吹き出しは**暗くしない小型版**（上部、`#coach` と同じ場所、タップで閉じる・数秒で消える）。F8 の光景・ウミガメで使う。選ぶ段は潜水を一時停止してから出す（ウミガメ、F8）。
- **飛ばす**：吹き出しの右上に「スキップ」（その台本を最後まで飛ばす）。操作させる段も飛ばせる。
- **アクセシビリティ**：吹き出しは `role="dialog"`・`aria-live`。

### 編集長のセリフを吹き出しに移す
- 章の始まり（`intro`）・クリアの褒め言葉（`praise`）・報酬の受け取り（「受け取る」の選ぶ段 → 所持金が増える演出）・海図の受け渡し（F6）を吹き出しで出す。

- ストーリーの文面（`CHAPTERS`）は変えない。吹き出し 1 つに収まらない長さは句点で 2〜3 段に分ける（自動）。

### (36) ウニは銛のボタンで取る
- **現行**：ウニの採取は、**カメラを持っているとき**にウニが前方 1.8m 以内にあると、**シャッターボタンがバールの操作**になる（`Game.ts` 1818・1865〜1871 行の `pryTarget`／`pry`、3 回押すとはがれる）。撮影とウニ取りが同じボタンなので、ウニの近くで写真が撮れず、ウニを撮ろうとしてはがしてしまうこともある。銛の持ち替えボタン（`btn-tool`）は手銛を持っていないと出ない（`!this.has('spear')`）。ウニ漁は掲示板の依頼（漁協）としおさい亭の仕込み（手銛を持ってから）の 2 つの入口がある。
- **方針**（要確認事項 **DO**）：
  1. ウニを取るのは**銛（持ち替えボタンで銛に替えた状態）のときだけ**。銛を持って前方 1.8m 以内にウニがあると、シャッター（銛の絵）が「突いてはがす」操作になる（3 回、今の `MISSION.pry`）。カメラのときはウニに反応しない（ふつうに撮影できる）。

  5. 川の銛の禁止（Phase 9 S6）はウニ漁に関係しない（ウニ漁は岩礁・冷たい海）。

### (37) ウニ漁から上がると画面の下の方に飛ばされる
- **現行の推定**：しおさい亭（`#kitchen`、`.screen.full` で `overflow-y: auto` のスクロールする画面）で、下の方にある「今日の仕込み：ウニ漁」のボタンを押して潜る → 浮上すると `toTitle()` → `kitchen.open()` → `harvestResult()` の順で戻るが、①しおさい亭の画面の**スクロール位置がそのまま残る**（潜る前の下の方の位置で開く）、②結果の表示（`#mg`）が `position: absolute; inset: 0` で**スクロールする箱の中**に置かれているため、スクロールした位置によっては結果の箱が画面の外（上）にあり、閉じるまでの間とその後に画面が下の方を指したままになる。ボート画面（`#title`）のスクロール位置も、ウニ漁へ行く前の位置が残る。
- **方針**（要確認事項 **DP**）：
  1. まず再現を確かめる（Playwright、390×844：しおさい亭を開いてウニ漁のボタンまでスクロール → 潜る → テストフックでウニ漁を終える → 浮上後の `#kitchen.scrollTop` と、`#mg` の箱の画面上の位置を記録）。
  2. 直し：ウニ漁から戻ったときは しおさい亭を**一番上（scrollTop = 0）**で開く。結果の表示 `#mg` は `position: fixed`（画面に対して固定）にして、スクロール位置に関係なく画面の中央に出す。結果を閉じたら「店の仕事」タブ（F3）の一番上が見える位置にする。ボート画面に戻るときも `#title` を一番上に戻す。
  3. F3 でしおさい亭をタブに分けると画面が短くなり、同じ問題は起きにくくなるが、`#mg` の固定と scrollTop の戻しは F3 と関係なく入れる。
  4. 確認：上の手順で、浮上後に しおさい亭の見出しと結果の箱が画面内に見えていること（390×844 と 844×390）。

### (4) 光景の円と「いつ潜っても見られるのか」

  - 特別な光景（`SCENES` 16 種）：**すでに確率**。1 回の潜水で、その地点・時間帯に合う光景の中から最大 1 つを `chance`（0.08〜0.25）で抽選する（`startDive` 1131〜1143 行）。章が求める光景（眠るマッコウクジラ・サンゴの一斉産卵）だけは、その章の間は**毎回必ず**出る（演出）。円は「章の光景＝最初から」「抽選の光景＝気配のトースト（`sense`）が出てから」表示（`sceneMarks`）。
  - 写真スポット（`SPOTS`、水色の円）：場所に固定の見どころで、**発見済みのマップでは常に全部の円が出る**（`spotMarks`）。いつ潜っても撮れる。
  - つまり「全部の円が常に出ている」と見えているのは主に写真スポットの水色の円と、章の光景の円。
- **方針**（要確認事項 **CV**）：
  1. 写真スポットの円は**ヒントが出たときだけ**：スポットから 45m 以内に近づくと小型吹き出し（またはトースト）「◯◯の見どころが近い…」が出て、そのときから円を出す。一度撮ったスポットの円は出さない（現行どおり）。
  2. 抽選の光景は現行どおり「気配の表示が出てから」円を出す。
  3. 章の光景も、最初から円を出すのをやめ、**編集長の吹き出しで場所の手がかり**（章の `intro`）を伝えたうえで、その場所に近づいて気配の表示が出てから円を出す（章の光景は最初の 1 回は必ず出る＝演出、の決まりは残す）。
  4. 写真スポットの「確率化」：スポットは地形の見どころなので常にあるが、**撮れる条件**に時間帯や天気を付けたものを一部に作る（例：「ラグーンの白い砂紋」は晴れの昼だけ光の網目が出る、「滝つぼの光の泡」は晴れか曇り）。条件に合わない日は気配の表示も円も出ない。対象と条件は F8 で一覧にして決める（全部に付けると撮れない日が続くので、9〜11 か所のうち 4 か所程度）。
  5. 光景の抽選確率は据え置き。実績画面の「？？？」のヒント文に「出会えるかは運しだい」を足す。

### (20) 光景に出会えたときの表示

## F10 川・河口の見た目 — 項目 (2)（**実装済み 2026-11-28**、`claude/fix2-f10`）

### 現行

### 解釈と方針（要確認事項 **CX**）
