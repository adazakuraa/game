## 手順

### ステップ1：設計（Opus）

- Phase 3 の全項目について、現行コードのどこをどう変えるかを `dive/docs/PHASE3-DESIGN.md` に書き、実装前にコミットする。特に次は設計で決め切ること：
  - 編集長の依頼：クリア時に報酬を受け取れるようにする（Phase 1 で章の報酬額は確定済み。受け取りの導線と未受け取り時の扱いを設計に書く）。Sランクのコツの教え方。依頼「夜行性の生き物を撮る」を「夜の魚を撮る」に変更する
  - 依頼掲示板：受注をやめたら依頼が消えず元の状態に戻るようにする。依頼を1つクリアしたら1つ追加する仕組み
  - 「銛が解放されたら、途中から食堂で依頼を受けるようにする」（Phase 1 §9-B の引き継ぎ）：Phase 1 では手銛購入後に食堂の注文が出る形で実装済み。この Phase 3 の項目が「掲示板の島民依頼も食堂へ移す」意味なのか、「食堂の注文の延長」なのか、現行実装とトラッカー文面から判断し、設計に結論と理由を書く。島民依頼を食堂へ移す場合は、掲示板との役割分担も設計する
  - 海中イベント：海で発生する依頼（ウミガメなど）の発生頻度を下げる具体的な頻度。「あと何秒」の残り時間表示は円の中にいるときだけにする。ウミガメのイベントで、ボタンタップで綱を切るモーションに入る流れ
  - 新しいマップの発見通知：必ず表示されるようにする（現状の出る・出ないのばらつきの原因を特定して設計に書く）
  - 光景・写真スポット：光景にも依頼と同様に範囲を示す円を表示する。写真スポットで写真を撮ると魚と同様にお金が獲得できる仕組み。報酬は各スポットで最初の1回だけにする。なお Phase 2 で特別な光景の報酬も写真報酬として1/7化している（§6-E）。光景の扱いを見直す場合は額の再検討も設計に含める

### ステップ2：実装（Sonnet）

- 設計に沿って実装する。変更は Phase 3 の範囲に必要な最小限に留める。
- セーブ形式（`blue-depths-save-v1`）を変える場合は、旧データからの移行かキーの版上げを必ず入れる。受注状態・クリア済み依頼・写真スポットの初回報酬済みフラグが、既存セーブで矛盾しないよう注意する。
- 検証：`cd dive && npm install && npm run artifact` が通ること。テストフック／自動プレイ（Playwright）で、編集長依頼の報酬受け取り、掲示板の受注キャンセルと依頼補充、ウミガメイベントのモーション、新マップ発見通知の表示、写真スポットの初回報酬を確認する。

### ステップ3：終了処理

- トラッカー Phase 3 のチェックボックスと進捗サマリーを実態に合わせて更新する。Phase 1 §9-B の項目は、結論に応じて未解決事項側もあわせて更新する。
- `dive/RESUME.md` を現状に書き直す。
- コミットして自分の作業ブランチに push し、アーティファクトをスキル `publish-artifact` の手順で更新する。
- 文脈使用率が約60%に達したら現在のステップを終えて新規作業を始めず、約70%で引き継ぎを書いて新セッションへ移る（スキル `session-handoff`）。

## 制約（再掲）

- 有料素材・外部 API・外部 CDN は使わない。
- スマホのタッチ操作が主前提。
- 依頼内容・条件・数値を勝手に要約したり削ったりしない。判断に迷う点は設計文書に「確認が必要な点」として残し、勝手に決めない。
