# IMPROVEMENT_TRACKER.md

登山ゲームの修正依頼を、原文の内容を削らずに管理するためのトラッカー。
各項目は実装・確認後に状態を更新する。要望の統合によって意味や条件を失わないこと。

## 運用ルール

-   [ ] 以下の要望を、明示的な指示なしに削除・省略・簡略化しない。
-   [ ] 複数の要望を同じ機能で実装する場合も、個別のチェック項目は残す。
-   [ ]
    既存実装との重複がある場合は、実装済みかどうかを確認して状態を更新する。単に項目を削除しない。
-   [ ] 要望同士に矛盾や依存関係がある場合は、勝手に解釈せず記録する。
-   [ ]
    山・アイテムの追加では、既存データとの重複を確認し、同じものを二重登録しない。
-   [ ] 実装状態は `未着手` / `調査中` / `実装中` / `実装済み` /
    `確認済み` / `保留` のいずれかで管理する。
-   [ ] 「実装済み」と「動作確認済み」を区別する。
-   [ ] 本ファイルの項目数や内容を、トークン節約などを理由に減らさない。

## Phase 1：景色・天候・環境表現

### 景色の整合性・実物準拠

-   [ ]
    キャンプごとに景色の整合性が取れない問題を修正する。
-   [ ]
    ルートや景色が実際のものに則しているか確認する。則していなければ、実際のものに近づける。
-   [ ] 見える星座も、実際のものに則するようにする。

### 天候・出発判断

-   [ ] 毎日晴れすぎているため、天候が多少悪い日があってもいいようにする。
-   [ ]
    天気の情報を踏まえて、何時に出発するかも自分で決められるようにしたい。
-   [ ]
    晴れの日に山頂に登るために無理をするか、曇りでもいいから道中安全に行くか、といった判断を、所要時間などを踏まえて自分で判断できるようにしたい。

### 太陽・鳥

-   [ ]
    日没と日の出は、もう少しはっきり太陽の輪郭が欲しい。
-   [ ] 鳥の出現頻度を下げる。たまに見るくらいでいい。

## Phase 2：リスク・報酬・道中アイテム

### リスク・緊張感

-   [ ] 適切なリスクがほしい。
-   [ ]
    凍傷になったりしても現状特段困らないため、凍傷に実害を持たせる。
-   [ ] 突風も無視しても困らない現状を改め、突風に実害を持たせる。
-   [ ] 体温が一定以下になることもない現状を改め、体温低下の仕組みを持たせる。
-   [ ]
    普通にプレイしていて死ぬことはないが、天候なども含め、下手したら死ぬくらいの緊張感は欲しい。
-   [ ]
    ただし、常に気を張っていると疲れるので、緊張感の付けすぎは良くない。バランスを取る。
-   [ ] 高山病のリスクもほしい。

### 報酬

-   [ ]
    山登りやタイムなどの報酬として、体力が増えたりするようにしてほしい。
-   [ ]
    報酬として、キャンプ間に設置できるセーブポイントを買えたりしてほしい。
-   [ ] スピードが上がる報酬はなしにする。

### 道中アイテム

-   [ ]
    道中のアイテムが不自然に光りすぎているので、もう少し地味にしてほしい。
-   [ ] アイテムの数は、キャンプとキャンプの間に3〜4個くらいにする。
-   [ ]
    いくつかのアイテムは道中で食べられるようにして、ちょっと回復できる、みたいな効果があってもいい。

## Phase 3：七大陸最高峰・山の解放・ガイド基準

### 七大陸最高峰と解放順

-   [ ] 七大陸最高峰は全部登れるようにする。
-   [ ]
    難易度が低い順に解放されて、無事クリアしたら次の山が解放されるようにする。
-   [ ] 全部クリアできたら、適切にほめる演出を入れる。
-   [ ] 全部クリア後のおまけとして、富士山が解放されてほしい。
-   [ ]
    それぞれの山ごとの特徴が、景色や道中のイベント、ギミック、リスクなどに反映されるようにする。そうでないと、ただの作業・繰り返しになってしまう。

### ロープの量の実物確認

-   [ ]
    ロープが多すぎると思うが、実際のそれらの山はどうなのか確認する。実際通りなら、このままでいい。

### 出発時の山の説明

-   [ ]
    ベースキャンプから出発するときに、どんな山かの説明が多少あるといい。記録帳と内容が重複しない範囲で。

### ガイド基準

-   [ ]
    ガイド基準がよく分からない問題を見直す。現状だと、普通に歩き続けたらシェルパ級になる区間もある。
-   [ ]
    逆に、それで基準+40分とかになることもある。基準の算出が分かりにくい状態を改善する。

### 下山の削除

-   [ ] 下山はいらないので削除する。

### 踏破の表示

-   [ ]
    登りきった山は、メニュー画面からそうと分かるようにしてほしい（踏破とかクリアみたいな感じで表示する）。

## Phase 4：移動・犬・ロープ視点・山頂・表示

### 歩行スピード

-   [ ]
    道中が長すぎて作業ゲーすぎる問題を改善する。
-   [ ]
    歩く音のスピードは変えずに、歩くスピードだけ速くするのはアリ。
-   [ ]
    テストのために、設定から歩くスピードを自由に数値で調整できるようにしてほしい。今のスピードから、10倍くらいまでの範囲で。
-   [ ]
    歩くスピードの最終的な値は、依頼者が設定を触って決める。勝手に確定しない。
-   [ ] 道中で飽きないような工夫は絶対に必要。

### 犬

-   [ ]
    犬の名前は自由に付けられるようにしてほしい。「犬を連れて行く？」で連れて行くを押したら、名前を入力させる。
-   [ ]
    犬を連れて行くとガクガクしていて挙動がおかしい問題を修正する（坂道だからかは分からない。原因は未確認として記録する）。
-   [ ]
    キャンプに置いていく選択肢も欲しい（現状にその選択肢があるかは未確認）。

### ロープの視点

-   [ ]
    ロープじゃないと登れないところで、ロープが斜めっていて違和感がある問題を修正する。真下にロープの視点があるべき。

### 山頂到達後

-   [ ]
    山頂に着いたあと、すぐクリア画面が出てきてしまう現状を改める。辺りを見回したりして達成感に浸る時間が欲しい。
-   [ ]
    山頂に自分が何か道しるべを残すような機能があってもいい（テキスト入力して中身を書く）。
-   [ ]
    任意のタイミングでクリア画面に行って、終わらせられるようにする。

### ボンベ残量表示

-   [ ]
    ボンベ残量あとわずかの表示は、5秒くらい出したら消していい。

## Phase 5：チュートリアル・ストーリー

### チュートリアルの文言・タイミング

-   [ ]
    チュートリアルの「見なくてもいい」という文言はいらないので削除する。
-   [ ]
    チュートリアルが出るのが一部早すぎる（ロープの付け替えや外すなど）。その行為が必要になる一瞬前くらいから出すようにする。
-   [ ]
    ロープに関する操作中に動いて中断されないようにしてほしい（そもそもアニメーション中は動けないようにしてほしい）。
-   [ ]
    滑落について「わざと足を滑らせる」の文言はいらないので削除する。実際滑落したときに画面を止めてチュートリアルを表示すればいい。

### ボンベのチュートリアル

-   [ ]
    チュートリアルのボンベは、交換と流量の変化がほぼ同時にあって分かりにくい。順を追ってやらせるようにする。
-   [ ] なぜそれをやるのかの説明も入れる。

### チュートリアル完了時の文言

-   [ ]
    チュートリアル完了時の「次は本物の山へ」という文言はいらないので削除する。
-   [ ]
    代わりに「この調子で七大陸最高峰を制覇しよう」みたいな感じの文言にする。

### ストーリー

-   [ ] ストーリーがほしい。
-   [ ]
    何のために今登っているのかとか、これからも登り続けるのかとか、そういう目的が現状ない。
-   [ ]
    チュートリアルとか山のクリア時とかにストーリーを挟んでおきたい（薄くていい）。
